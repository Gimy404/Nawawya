# التقرير الأول — الفحص الهندسي والتجريبي للتطبيق الحالي

> فحص سطر بسطر لـ ١٠٠٨٨ سطر Kotlin في `app/src/main`، مع تتبّع كل زِرّ من اللمسة
> إلى الحالة النهائية في `NawawiaViewModel`. كل بند أدناه فيه مَوضِع الكود الذي يُثبته.

---

## أولًا: ما هو ممتاز فعلًا في التطبيق (لا نلمسه)

قبل النقد — هذه أصول حقيقية وقوية، وهي سبب أن التطبيق يستحق إعادة التصميم لا الرمي:

| الأصل | الدليل |
|---|---|
| **المتن أصيل ومضبوط بالتشكيل، ٤٢ حديثًا كاملة** بلا نقص ولا فجوات | `NawawiAuthenticCatalogPart1/2.kt` — تحقّقتُ من `number = 1..42` متسلسلة |
| لكل حديث: تخريج موثّق، وبيان الراوي، ومفردات مشروحة، وفوائد، ومقاطع مرتّبة للحفظ | بنية `AuthenticHadithSeed` — ١٩ حقلًا لكل حديث |
| `ContentValidator` ببوابة تحقّق سباعية وبصمة SHA-256 | `ContentValidator.kt` |
| طبقة `domain` نقية تمامًا بلا أي `android.*` — تُصرَّف وتُختبر منفصلة | تحقّقت عمليًّا: صرّفتُ `domain/` + `core/` بـ kotlinc مستقل ونجح |
| `AppClock` كمَنفذ وحيد للوقت، و`StreakEngine` يحمي من تلاعب الساعة | `AppClock.kt`, `StreakEngine.kt` |
| `LinkGuard` يمنع أي رابط شرح خارج نطاقات علمية موثوقة | `LinkGuard.kt` |
| SM-2 للتكرار المتباعد، و٤٢ اختبار وحدة قائمة | `Sm2Scheduler.kt`, `GameSystemsAndStreakTest.kt` |

**الخلاصة:** المحرّك والمحتوى سليمان. المشكلة في الواجهة، والصوت، ومنطق بعض الأزرار.

## ثانيًا: العِلّة الكبرى — صوت آلي يقرأ حديث رسول الله ﷺ

هذه أخطر نقطة في التقرير، وهي بالضبط ما شكوتَ منه.

`AudioController.kt` لا يشغّل أي تسجيل بشري. هو يفعل أمرين:

**١) يقرأ المتن بمحرّك النطق الآلي في أندرويد (TTS):**

```kotlin
// AudioController.kt:7
import android.speech.tts.TextToSpeech
// AudioController.kt:236-239
engine.setSpeechRate(_state.value.speed.multiplier)
engine.speak(subText, TextToSpeech.QUEUE_FLUSH, null, "nawawia_utterance")
```

**٢) وإن لم يجد محرّك نطق عربيًا، يولّد نبرات صوتية رياضية (موجة جيبية) ويُسمعها بدلًا من الحديث:**

```kotlin
// AudioController.kt:332-336
val envelope = sin(PI * i / numSamples)
val angle = 2.0 * PI * i * frequencyHz / sampleRate
samples[i] = (sin(angle) * 10000 * envelope).toInt().toShort()
```

وهذا يصطدم بثلاثة أمور في وقت واحد:

1. **يخالف قاعدة المشروع المكتوبة بنفسه.** `AUDIO_GUIDE.md` بندها الثالث حرفيًّا:
   *«يُمنع استخدام تحويل النص إلى كلام آليًا (TTS) لقراءة الأحاديث النبوية»*. القاعدة
   موجودة في التوثيق ومخروقة في الكود.
2. **مشكلة أدب وشرع.** قراءة حديث النبي ﷺ بصوت آلة، بسرعة قابلة للتعديل (`setSpeechRate`)،
   مع لحن وتشكيل خاطئين — ثم الاستعاضة عن كلامه ﷺ بـ«طنين» حين يغيب المحرّك. هذا ما لا
   يُقبل في تطبيق مرجعه النبوة.
3. **`assets/audio/` غير موجود أصلًا.** تأكّدتُ: المجلد غير منشأ ولا ملف صوتي واحد في
   المشروع. فكل زِرّ صوتي في التطبيق — وهي ٦ مواضع — إمّا ينطق آليًّا أو يُطنّ.

**الحكم:** يُحذف TTS ومولّد النبرات بالكامل. لا صوت إلا تسجيل بشري، وإن غاب التسجيل
تُعرض حالة صريحة محترمة بدل الصوت المزيّف.

## ثالثًا: منطق الأزرار والشاشات — ما وجدتُه معطوبًا

### ١. أربعة أزرار تفعل الشيء نفسه في شاشة واحدة

في `PathScreen.kt` وحدها، لفتح نفس الحديث:

| الزِرّ | الموضع | ما يفعله فعلًا |
|---|---|---|
| «ابدأ التعلم» | `PathScreen.kt:122` | `onStartLearningClick` |
| «تابع من هنا (الحديث ن)» | `PathScreen.kt:214` | **نفس** `onStartLearningClick` |
| «ابدأ الوحدة» (×٦ وحدات) | `PathComponents.kt:238` | `openReader` لأول حديث غير متقَن |
| عقدة الحديث نفسها | `PathScreen.kt:193` | `openReader` |

زرّان مختلفا النص يستدعيان نفس الدالة حرفيًّا. وفوقهما «المراجعة السريعة» و«تصفح
الأحاديث» وهما يكرّران تبويبين موجودين أصلًا في شريط التنقّل السفلي. النتيجة: ٦ نداءات
متنافسة في أول شاشة يراها المستخدم، فلا يعرف أين يضغط. ديولينجو عنده **نداء واحد**: العقدة النشطة.

### ٢. «ابدأ التعلم» لا يبدأ درسًا

```kotlin
// NawawiaViewModel.kt:386
fun onContinueLearningClick() {
    val targetHadith = _uiState.value.currentContinueHadith ?: return
    openReader(targetHadith.id)   // ← يفتح القارئ، لا الدرس
}
```

الزِرّ اسمه «ابدأ التعلم» وسلوكه «افتح صفحة قراءة». التسمية تَكذِب على الفعل.

### ٣. القفل على العقد ديكور فقط

```kotlin
// NawawiaViewModel.kt:400
fun onNodeClick(hadith: Hadith) {
    openReader(hadith.id)   // ← بلا أي فحص لحالة العقدة
}
```

`getNodeStatus` يحسب `LOCKED` وترسم العقدة أيقونة قُفل… ثم الضغط يفتح الحديث عاديًا.
فالتقدّم المتسلسل كله إيحاء بصري بلا أثر.

### ٤. ثلاث عتبات إتقان مختلفة تتصارع على نفس الرقم

| العتبة | الموضع | الاستخدام |
|---|---|---|
| `>= 80` | `NawawiaViewModel.kt:168` | تُعلِن العقدة «متقَن» |
| `>= 60` | `NawawiaViewModel.kt:189, 194` | تَعُدّ الحديث منجزًا في الأوسمة والوحدات |
| `>= 60` | `PathScreen.kt:168` | تَعُدّ المنجز في شريط الوحدة |
| `< 80` | `NawawiaViewModel.kt:406` | تختار هدف «ابدأ الوحدة» |

أثر مرئي مباشر: حديث عند ٦٥٪ يظهر في شريط الوحدة محسوبًا ضمن «الإنجاز ٧/٧»، وفي نفس
اللحظة عقدته تحمل نجمة «قيد التعلم» لا علامة إتقان. المستخدم يرى رقمين يتناقضان.

### ٥. شريط التقدّم في الدرس يرجع للخلف

عند الخطأ، يُعاد السؤال إلى آخر الطابور:

```kotlin
// NawawiaViewModel.kt:758
val updatedQuestions = lesson.questions + currentQ
```

و`progressFraction = (currentIndex + 1) / questions.size`. فالمقام يكبر والبسط ثابت:
أخطأتَ في السؤال الأول من ٦ → التقدّم ينزل من ١/٦ إلى ١/٧. الشريط **يتقهقر** أمام عين
المستخدم عند كل خطأ. وبلا سقف: الخطأ المتكرّر يضيف نسخة كل مرة، فالدرس قابل للامتداد بلا نهاية.

### ٦. سؤال «صِل العبارات» لا يمكن الخطأ فيه أبدًا

- `canCheckAnswer` لا يُفعّل زِرّ التحقّق إلا إذا `matchedPairIds.size == matchPairs.size`
- و`matchedPairIds` لا يزيد إلا عند مطابقة **صحيحة** (`rightId == leftId`)
- ثم `checkCurrentAnswer` يحكم: `isCorrect = matchedPairIds.size == matchPairs.size`

أي أن زِرّ التحقّق لا يُضغط إلا وكل الأزواج صحيحة سلفًا. السؤال بلا صعوبة ولا نتيجة.

### ٧. المراجعة تكتب تقدّمها على حديث واحد فقط

`finishLessonSession` يحدّث SM-2 لـ `lesson.hadithId` وحده — وهو حديث **السؤال الأول**.
و«المراجعة السريعة» تبني جلسة من ٤٢ سؤالًا من ٤٢ حديثًا مختلفًا:

```kotlin
// NawawiaViewModel.kt:570
ReviewMode.QUICK_10_MIN -> state.hadiths.mapNotNull { h ->
    state.questionsByHadithId[h.id]?.firstOrNull()
}
```

فتُراجع الأربعين كلها، ويُسجَّل الإنجاز على الحديث الأول فقط. باقي الـ ٤١ لا يتحرّك
جدول مراجعتها. هذا يُفقد خوارزمية SM-2 معناها في أهم وضع مراجعة.

### ٨. المراجعة تُعيد نفس السؤال حرفيًّا في كل مرة

`firstOrNull()` في الأوضاع الثلاثة. فأول سؤال لكل حديث هو نفسه في كل جلسة مراجعة، أبد
الدهر. المستخدم يحفظ **موضع الإجابة**، لا الحديث.

### ٩. القلوب بلا أثر

عند نفاد القلوب تُرفع ورقة تنبيه (`showHeartsEmptySheet = true`) ولا يُنهى الدرس ولا
يُمنع التقدّم. فالعقوبة إشعار يُغلق ويُكمل.

### ١٠. «١٠ دقائق يوميًا» رقم غير مُقاس

```kotlin
// NawawiaViewModel.kt:838
val nextMinutes = state.totalMinutesSpent + 3
```

كل درس = ٣ دقائق ثابتة، بصرف النظر عن الزمن الحقيقي. فالهدف اليومي «١٠ دقائق» يتحقّق
بأربعة دروس ولو استغرقت ٤٠ دقيقة أو ٤٠ ثانية. والوعد المكتوب في الواجهة غير مُقاس.

### ١١. نتيجة الدرس مقامها خطأ

```kotlin
// NawawiaViewModel.kt:849
val totalQuestionsCount = (correctFirstTryCount + correctAfterRetryCount).coerceAtLeast(1)
val scorePct = ((correctFirstTryCount * 100) / totalQuestionsCount)
```

المقام هو عدد الإجابات **الصحيحة** لا عدد الأسئلة. فالنسبة تقيس «نسبة ما ضبطته من أول
مرة ممّا ضبطته» لا «من أصل الدرس».

### ١٢. رسالة ثابتة تدّعي مصدرًا بعينه

```kotlin
// NawawiaViewModel.kt:495
it.copy(snackbarMessage = "رابط موثوق: جاري فتح الشرح في الدرر السنية")
```

تُقال لأي رابط يجتاز `LinkGuard` ولو كان من نطاق آخر مسموح. إخبار غير صحيح.

## خامسًا: الإشعارات — غير موجودة بالكلّية

بحثتُ في كل `.kt` و`.xml` و`.kts`. لا `NotificationManager`، ولا `WorkManager`، ولا
`AlarmManager`، ولا `POST_NOTIFICATIONS`. الأثر الوحيد عمود في قاعدة البيانات:

```kotlin
// NawawiaDatabase.kt:149
db.execSQL("ALTER TABLE user_state ADD COLUMN reminderHour INTEGER NOT NULL DEFAULT 20")
```

عمود `reminderHour` مُهاجَر إليه في `MIGRATION_1_2`، ولا تقرؤه ولا تكتبه أي شاشة ولا أي
دالة. وشاشة الإعدادات لا تعرض أصلًا خيار تذكير. فالتطبيق — وهو تطبيق عادة يومية —
لا يستطيع تذكير أحد بشيء. (الخطة الكاملة للإشعارات في التقرير الرابع.)

## سادسًا: التصميم — لماذا الواجهة «مش عاجبة»

### كل شيء بطاقة، وكل البطاقات متماثلة

البطاقة الواحدة المتكرّرة: `RoundedCornerShape(20.dp)` + `border(2.dp, outline)` +
`background(surface)`. مطبّقة على: بطاقة الترحيب، شريط الوحدة، بطاقة الحديث في الفهرس،
بطاقة إحصاءات الحساب، بطاقة الوسام، بطاقة وضع المراجعة. فالشاشة كلها إيقاع واحد: مستطيل
دائري الزوايا، ثم مستطيل دائري الزوايا، ثم مستطيل دائري الزوايا. لا هيكل بصري ولا تفاوت
أهمية — وهذا أشهر أثر لواجهة مولّدة آليًّا.

### ست وحدات لها ألوان… والواجهة تتجاهلها

```kotlin
enum class UnitColorRole { BRAND, GOLD, INFO, PLUM, CLAY, SAND }   // Models.kt:6
```

مُسندة لكل وحدة في `ContentLoader.kt:53-58`. وبحثتُ في `ui/` كلها:
**`colorRole` غير مستخدم ولا مرة واحدة.** و`NawawiaColors` لا يحتوي أصلًا على
`plum` ولا `clay` ولا `sand`. فالوحدات الست كلها أخضر واحد — مع أن النيّة كانت تمييزها.

### «الطريق» ليس طريقًا

```kotlin
fun computeWindingOffsetDp(indexInUnit: Int): Dp {
    val wave = sin(indexInUnit * 1.05).toFloat()
    return (wave * 44f).dp
}
```

`sin(i × 1.05)` ليس دورة منتظمة: الإزاحات تخرج ٠، ٣٨، ٤٠، ٥، −٣٧، −٤٢… فالعقد تترنّح
بلا نَسَق بدل أن تتثنّى في مسار. ولا خط يصل بينها، فهي نقاط متناثرة لا طريق. ولا عقدة
نهاية وحدة، ولا احتفال، ولا تمييز للعقدة النشطة.

### الخطوط: واحد منها خطأ على المحتوى

ثلاث عائلات. `Baloo Bhaijaan 2` — خط مدوّر طفولي — مستخدم للعناوين وكل نصوص الأزرار.
والأسوأ: نصّ السؤال في الدرس يُرسم به:

```kotlin
// LessonScreen.kt:168
style = MaterialTheme.typography.headlineMedium   // ← Baloo Bhaijaan 2
```

وأسئلة «أكمل الفراغ» متنها من الحديث مشكَّل. فالتشكيل يُرسم بخط دِعائي مدوّر لم يُصمَّم
له، فيضطرب موضع الحركات وتضعف القراءة — ويضيع الفصل بين كلام النبوة وأثاث الواجهة، وهو
فصل كان المشروع نفسه قد اشترطه.

### اللون الأساسي هو عين كليشيه الفئة

`#12805C` أخضر زمردي. وهو لون كل تطبيق قرآن وحديث في المتجر. لا يميّز نواوية بشيء.

### حالة ميتة في الكود تكشف نيّة مفقودة

`ActiveLessonUiState.feedbackTextAr` تُكتب في الـ ViewModel ولا تُقرأ في `LessonScreen`
أبدًا. الشاشة تعرض بدلًا منها نصًّا ثابتًا: «صحيح» / «غير صحيح». فحتى التغذية الراجعة
المتنوّعة كانت منويّة ثم سقطت.
